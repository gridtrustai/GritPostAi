# GridTrust AI: Phase 1 hand-off

This package holds the Phase 1 update for **https://github.com/gridtrustai/GridTrustAI**
(TSYP14 EnergyMind Tunisia challenge). The proposal Google Doc has already been updated
separately; only the GitHub repository still needs these changes.

**Deadline: Phase 1 submission, 15/10/2026. Push before submitting the proposal**, because
the proposal links to this repo and quotes its results.

## What is in this folder

| Path | What it is |
|---|---|
| `patches/0001-…` to `0004-…` | The 4 commits to add on top of the current repo (keeps git history) |
| `repo/` | The complete repository after the 4 commits (fallback if the patches do not apply) |
| `AI_AGENT_PROMPT.md` | A ready-to-paste prompt if you use an AI coding assistant to do this |
| `README_FIRST.md` | This file |

The 4 commits:
1. **Phase 1 upgrade:** 5-meter feeder with 10 labelled events, detection that separates grid events from data-quality problems, escalation policy, decision log, evaluation, figures, tests, docs.
2. **UCI loader:** `--uci` option to run the same pipeline on real measured power from UCI ElectricityLoadDiagrams20112014.
3. **.gitignore:** stops the raw dataset files (~700 MB) from being committed by mistake.
4. **Data source links:** a "Data sources" table in the README and a download link in `data/DATASET_NOTE.md`.

## Option A: apply the patches (recommended)

Needs git and push (Write) access to the repo. The patches expect the repo's latest commit to
be `85b7592 phase 1`.

```bash
git clone https://github.com/gridtrustai/GridTrustAI.git
cd GridTrustAI
git log --oneline -1                 # should show: 85b7592 phase 1
git am /path/to/GridTrustAI_handoff/patches/*.patch
git log --oneline -5                 # the 4 new commits on top of 85b7592
```

Check that it works (Python 3.10+), then push:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v      # expect: Ran 16 tests ... OK
git push origin HEAD
```

If `git am` stops with a conflict (someone pushed something new), run `git am --abort` and use
Option B.

## Option B: copy the files

```bash
git clone https://github.com/gridtrustai/GridTrustAI.git
cd GridTrustAI
rm -rf .idea                                   # IDE folder, should not be in the repo
```

replace existing files.

## Optional: run on real data (UCI)

Only if there is time; the submission is complete without it.

1. Download the dataset (about 250 MB zip): https://archive.ics.uci.edu/dataset/321/electricityloaddiagrams20112014
2. Run, from the repo folder:
   ```bash
   python src/generate_dataset.py --uci path/to/electricityloaddiagrams20112014.zip
   python src/detect_anomalies.py --uci
   python src/evaluate.py --uci path/to/electricityloaddiagrams20112014.zip
   ```
   Reading the file takes a minute or two. If the zip from UCI contains more than one file,
   extract it and pass the path to `LD2011_2014.txt` instead.
3. Results appear in `results/uci/metrics.json` and `figures/*_uci.png`. Commit those
   outputs plus `data/uci_*.csv`, **never the downloaded dataset itself** (the .gitignore
   already blocks it).
4. If the numbers look reasonable, add them to the README results section, clearly labelled
   "UCI measured power, simulated voltage/current and injected events".

If anything fails on the real file, do not try to fix it tonight: leave the UCI outputs out
and submit. The synthetic results are the Phase 1 results.

## Rules for anyone editing before submission

- Do not change thresholds in `src/detect_anomalies.py` or `src/escalation.py`: the README and the proposal quote results produced with them.
- Do not re-word results as real-world performance. All results are on synthetic data or on real power with simulated faults, and the README says so.
- If you change any code, rerun `generate_dataset.py`, `detect_anomalies.py`, `evaluate.py` and the tests, and make sure the README numbers still match `results/metrics.json`.
